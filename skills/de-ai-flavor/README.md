# 去AI味 (de-ai-flavor)

> 把 AI 生成的文本，改写成有经验的朋友在认真分享的样子。

[![npm version](https://img.shields.io/npm/v/de-ai-flavor.svg)](https://www.npmjs.com/package/de-ai-flavor)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)
[![Node](https://img.shields.io/badge/node-%3E%3D14-green.svg)](https://nodejs.org/)

---

## 这是什么

`de-ai-flavor` 是一个**中文去 AI 味改写技能包**，核心交付物是 `SKILL.md`——一份给 AI 看的五步改写工作流（作者改写 → 质检员诊断 → 针对性修复 → 验收 → 保存结果）。你可以把它装到任何支持自定义 Skill 的 AI 编程工具里（Cursor、Codex、Claude Code 等），让 AI 帮你把 AI 写的稿子改成"真人写的"。

同时附带一个 CLI 校验工具 `de-ai-flavor`，用于检查文本是否还残留 AI 特征（禁用词、个人视角、句式变化度、排比句检测等）。

**核心原则：不缩减原文内容。** 改写只改变风格，不删减信息。

---

## 为什么要使用

AI 写的稿子有几个让人一眼看穿的毛病：

| 特征 | 表现 | 读者感受 |
|------|------|----------|
| **套话连接词** | "首先 / 其次 / 最后 / 综上所述 / 值得注意的是" | "又在念报告" |
| **商业黑话** | "赋能 / 痛点 / 底层逻辑 / 闭环 / 赛道" | "在写 PPT 吧" |
| **抽象形容词** | "显著提升 / 至关重要 / 不可或缺" | "啥也没说" |
| **端水结构** | "虽然 A，但是 B，综上" | "作者没立场" |
| **完美平滑** | 句长均匀、无情绪、无个体经验 | "这是机器人" |
| **段末升华** | 每段结尾强行总结一句"金句" | "在写公众号" |

这些毛病直接影响：

- 📉 **可读性**：读起来累，三段就开始跳读
- 🤖 **信任感**：读者一眼识破"这是 AI 写的"，文章公信力归零
- 📋 **投稿 / 审核**：很多平台开始用 AI 检测器，过不了
- 💼 **职场沟通**：写汇报、写周报、写邮件全是这种调，老板看了觉得你只会用 AI

`de-ai-flavor` 的目标是把"AI 生成的稿子"改成"有经验的朋友在跟你聊"——保留所有信息，只换说话方式。

## 效果对比

### 示例 1：典型"教科书式"AI 稿

**改写前**（AI 味很重）

> 在当今社会，建立健康的恋爱关系对于现代都市青年而言具有重要意义。首先，良好的沟通是维系感情的基础。双方应当坦诚表达自己的感受与需求，避免误解与冲突的累积。其次，尊重彼此的个人空间同样不可或缺。每个人都拥有独立的人格与生活方式，过度依赖或控制只会适得其反。最后，共同成长是长期关系的核心动力。双方应在支持彼此事业与梦想的基础上，共同面对人生的挑战。综上所述，建立健康的恋爱关系需要沟通、尊重与共同成长这三个关键要素。希望广大青年朋友能够理性看待爱情，积极经营自己的感情生活。

**改写后**（靠谱朋友风格）

> 我跟你说啊，现在谈恋爱这事儿，比以前复杂多了。不是因为人不真诚了，是大家脑子里装的选项太多了，反而不知道挑哪个。
>
> 先说沟通。这个是老生常谈，但确实是基石。我之前谈过一个，每次想跟她聊聊"我们俩最近哪儿不对劲"，她就觉得我在挑事儿。后来我才搞明白，沟通不是上来就摆事实讲道理，而是先承认"我也有一部分问题"。这一句话说出来，氛围就完全不一样了。
>
> 然后是空间。这事儿看起来简单，实际上特别容易踩线。我有个朋友，控制欲特别强，恨不得对方每条微信秒回，结果三个月就分了。后来他反思，说"我以为我在乎她，其实是我怕她不在乎我"。你看，根源还是安全感的问题，不是空间的问题。
>
> 最后是共同成长。这个听起来有点鸡汤，但确实是那么回事。我观察身边过得久的情侣，要么是一起在某些事上变好的，要么是至少互相看得起对方在努力的。最怕的是一方使劲往前跑，另一方原地不动，时间长了根本聊不到一块去。
>
> 反正是这么回事吧。沟通、空间、成长——听着像三个并列的要点，其实是一回事：别把自己弄丢了，也别把对方委屈坏了。

**质检评分**

| 维度 | 改写前 | 改写后 |
|------|--------|--------|
| 结构（无总分总） | 2 | 9 |
| 词汇（无套话） | 1 | 9 |
| 语气（像人说话） | 1 | 9 |
| 个体经验 | 0 | 9 |
| 真实情绪 | 1 | 8 |
| 不完美感 | 1 | 8 |
| **平均分** | **1.0** | **8.7** |

### 示例 2：技术介绍类

**改写前**（产品说明书味）

> Cursor 是一款基于 AI 的代码编辑器，它能够显著提升开发效率。首先，Cursor 支持智能代码补全功能，可以根据上下文预测开发者的意图。其次，它具备强大的代码生成能力，开发者只需提供注释，Cursor 即可自动生成相应的代码实现。最后，Cursor 还提供了实时代码审查功能，能够帮助开发者及时发现并修复潜在问题。综上所述，Cursor 是现代开发者不可或缺的工具。

**改写后**（用过一年的人的真实反馈）

> Cursor 我用了一年多了，说说真实感受。
>
> 智能补全这个功能吧，刚上手会觉得"哇塞好神奇"，用一段时间就变成"嗯就这样"。真正提升效率的不是单个补全，而是 Tab 键一直按下去那种"代码自己长出来"的感觉，省掉的是来回切换窗口的精力。
>
> 代码生成这块儿我用得比较多的是写注释让它生成函数。准确率大概七成——简单函数没问题，复杂业务逻辑就得改半天。但是！哪怕不准，省下来的时间也值回票价了，因为不用从零开始写。
>
> 代码审查功能说实话我用得不多。可能我写代码比较规矩，它提的建议经常是"你这里可以加个类型注解"之类的，锦上添花。
>
> 最后说一句，Cursor 不是银弹。我同事拿它写 Python 项目写得飞起，但搞底层 C 的就觉得不好用。这玩意儿还是看你用在什么场景，别指望一键提效 10 倍。

## 工作流程（我们是怎么做的）

```
┌─────────────────────────────────────────────────┐
│  第 0 步  读取 config.json，生成个性化 Prompt    │
│          persona / style_level / 禁用词...       │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  第 1 步  作者改写                               │
│          AI 扮演配置的角色，按风格改写原文        │
│          ⚠️ 强制要求：原文字数一个都不能少       │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  第 2 步  质检员诊断（10 个维度 + 内容完整性）    │
│          结构 / 词汇 / 语气 / 个体经验 / 情绪    │
│          不完美感 / 困惑度 / 突发性 / 端水 / 装饰 │
│          + 改写后是否漏掉原文要点？             │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  第 3 步  对照诊断结果再次改写                   │
│          逐条修复问题，仍保持不缩减             │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  第 4 步  验收                                   │
│          7 项标准全部通过才输出                 │
│          （最多循环 max_revision_iterations 次）  │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  第 5 步  保存到 .output/de-ai-flavor/{时间戳}/   │
│          original.txt / final.txt / diagnose.json │
└─────────────────────────────────────────────────┘
```

### 分析维度（10 个 + 内容完整性）

我们基于这 10 个维度判断一篇文章是不是 AI 写的，每个维度 0-10 分（10 = 完全像真人）：

1. **结构**：有没有"总分总"、教科书式标题、整齐分隔线
2. **词汇**：有没有套话（赋能、痛点、底层逻辑、首先其次最后）
3. **语气**：像不像人在说话，还是念报告
4. **个体经验**：有没有"我试了…""我遇到…"
5. **情绪**：有没有真实情绪波动（吐槽、犹豫、后悔）
6. **不完美感**：有没有暴露思考局限、偏见、不确定
7. **困惑度**：上下文衔接是不是太顺畅，有没有跳跃感
8. **突发性**：句子长短是不是有变化
9. **端水感**：有没有过分平衡的两面论证（虽然…但是…）
10. **符号装饰**：有没有 emoji、过度对齐的分隔线

外加一项硬性检查：**内容完整性**——改写后是否漏掉原文的任何要点？如果漏了，即使其他分数高也算不及格。

详见 [`reference.md`](./reference.md)。

## 安装

### 方式 A：npm 全局安装（推荐）

```bash
npm install -g de-ai-flavor
```

装完后：

- CLI 工具可用：`de-ai-flavor "你的文本"`
- Skill 文件会下载到 npm 包内，需要手动复制到工具的 skill 目录（见下方）

### 方式 B：手动安装 Skill 文件

不管用什么工具安装，最终都需要把 `SKILL.md` 和 `config.json` 放到工具能识别的位置。

```bash
# 全局装好后，文件一般在：
# Linux/macOS: /usr/local/lib/node_modules/de-ai-flavor/
# Windows:     %AppData%\npm\node_modules\de-ai-flavor\
```

把整个 `de-ai-flavor` 目录复制到对应工具的 skills 目录即可（见下方工具章节）。

### 方式 C：从 GitHub 克隆

```bash
git clone https://github.com/Boom-Caoq/de-ai-flavor.git
cd de-ai-flavor
```

## 使用

### 在 Cursor 里使用

Cursor 支持自定义 Agent Skills（`~/.cursor/skills/` 或 `.cursor/skills/`）。

**第 1 步：复制 skill 文件**

```bash
# 个人技能（所有项目可用）
mkdir -p ~/.cursor/skills
cp -r node_modules/de-ai-flavor ~/.cursor/skills/de-ai-flavor
# 或从 GitHub 克隆：
# cp -r /path/to/de-ai-flavor ~/.cursor/skills/de-ai-flavor

# 项目技能（仅当前项目可用）
mkdir -p .cursor/skills
cp -r node_modules/de-ai-flavor .cursor/skills/de-ai-flavor
```

**第 2 步：让 Cursor 加载**

重启 Cursor 或刷新窗口（`Ctrl/Cmd + Shift + P` → "Developer: Reload Window"）。

**第 3 步：调用**

直接在 Cursor 聊天框里说：

```
用 de-ai-flavor 技能帮我改写下面这段：
[粘贴你的 AI 文本]
```

或者更明确的版本：

```
按 SKILL.md 的工作流，扮演"靠谱朋友"风格，把下面这段改成自然的人类写作风格。
不要缩减任何内容。
[粘贴你的 AI 文本]
```

Cursor 会自动读取 `SKILL.md` 并按 5 步流程执行改写、诊断、修复、验收，最后输出结果。

### 在 Codex 里使用

Codex（OpenAI 的 AI 编程工具）同样支持自定义 Skill。

**第 1 步：找到 Codex 的 skills 目录**

Codex 默认在 `~/.codex/skills/`（个人）或项目根目录的 `.codex/skills/`（项目）。

**第 2 步：复制**

```bash
mkdir -p ~/.codex/skills
cp -r node_modules/de-ai-flavor ~/.codex/skills/de-ai-flavor
```

**第 3 步：调用**

在 Codex 对话里说：

```
用 de-ai-flavor 技能改写下面这段：
[粘贴你的 AI 文本]
```

或带配置：

```
用 de-ai-flavor 技能，按 config.json 里的"技术博客"预设改写下面这段：
[粘贴你的 AI 文本]
```

### 在 Claude Code 里使用

Claude Code 支持 `.claude/skills/` 目录。

```bash
mkdir -p ~/.claude/skills
cp -r node_modules/de-ai-flavor ~/.claude/skills/de-ai-flavor
```

调用：

```
请使用 de-ai-flavor 技能改写以下文本：
[粘贴你的 AI 文本]
```

### 在其他 AI 编程工具里使用

任何支持"加载 Skill 文件 → 读取 SKILL.md 作为系统提示"的工具都可以：

1. 把 `de-ai-flavor/` 整个目录复制到工具的 skills 目录
2. 让 AI 读取 `SKILL.md` 作为工作流指引
3. 按 `config.json` 的配置生成个性化 Prompt
4. 执行 5 步流程

工具支持对照表（不完全）：

| 工具 | Skill 目录 | 支持情况 |
|------|-----------|----------|
| Cursor | `~/.cursor/skills/` | ✅ 原生支持 |
| Codex | `~/.codex/skills/` | ✅ 原生支持 |
| Claude Code | `~/.claude/skills/` | ✅ 原生支持 |
| Continue | `~/.continue/skills/` | ✅ 支持 |
| Aider | 手动注入 Prompt | ⚠️ 需要手动复制 SKILL.md 内容 |
| 自定义 Agent | 任意位置 | ✅ 读取 SKILL.md 即可 |

### CLI 工具使用

装好包之后，可以直接在命令行校验文本：

#### 基本校验

```bash
de-ai-flavor "首先，其次，最后，综上所述"
```

输出示例：

```
============================================================
去AI味 - 文本质量验证报告
============================================================
文本长度: 12 字符
验证时间: 2026-09-10T11:00:00.000Z

【检查结果】
整体状态: ❌ 未通过

1. 禁止词汇检查: ❌ 未通过
   发现 4 处:
   - "首先" 出现 1 次
   - "其次" 出现 1 次
   - "最后" 出现 1 次
   - "综上所述" 出现 1 次
   ...
```

#### 从文件校验

```bash
de-ai-flavor --file article.txt
```

#### JSON 格式输出

```bash
de-ai-flavor --json "你的文本"
```

输出 JSON 结构（方便程序调用）：

```json
{
  "timestamp": "2026-09-10T11:00:00.000Z",
  "text_length": 12,
  "checks": {
    "ban_list": { "found": [...], "passed": false },
    "personal_voice": { "i_count": 0, "we_count": 0, "has_sufficient": false },
    "sentence_uniformity": { "variance": "0.5", "is_varied": false },
    "parallelism": { "max_parallel_count": 0, "is_acceptable": true }
  },
  "summary": { "passed": false, "issues": [...] }
}
```

#### 在 Node.js 里调用

```javascript
const { validate, formatResult } = require('de-ai-flavor');

const text = '首先...其次...最后...综上所述...';
const result = validate(text);

console.log(formatResult(result));
// 或者直接拿 JSON
console.log(JSON.stringify(result, null, 2));
```

## 配置（config.json）

`config.json` 是核心配置项，改完保存即可生效，下次 AI 会自动按新配置工作。

### 可配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `persona` | 改写后的说话角色 | `靠谱朋友` |
| `style_level` | 口语化程度 1-10 | `6` |
| `allow_profanity` | 是否允许脏话 | `false` |
| `allow_humor` | 是否允许吐槽、自嘲 | `true` |
| `allow_interruptions` | 是否允许突然跑题 | `false` |
| `personal_experience` | 个人经历密度 | `some` |
| `length_control` | 长度控制 | `preserve`（不缩减） |
| `data_precision` | 数据精确度 | `fuzzy` |
| `max_revision_iterations` | 最大修订轮数 | `3` |
| `ban_words` | 额外禁用词 | `[]` |
| `output_format` | 输出格式 | `plain` |

### 4 个内置预设

直接在调用时指定预设名即可，不用改 config：

| 预设 | 适用场景 | 风格 |
|------|----------|------|
| **标准知识分享** | 公众号、知识星球、知乎 | 靠谱朋友，口语度适中 |
| **技术博客** | 个人博客、技术公众号 | 技术博主，保留精确数据 |
| **论坛问答** | 知乎回答、V2EX、Reddit | 论坛老手，允许吐槽 |
| **职场沟通** | 周报、邮件、汇报 | 职场前辈，最克制 |

示例（指定预设）：

```
用 de-ai-flavor 技能，按"技术博客"预设改写下面这段：
[文本]
```

## 进阶

### 自定义 Prompt

高级用户可以直接编辑 `SKILL.md`，调整每一步的 Prompt。比如：

- 想让改写更克制？把 `style_level` 改成 `3`
- 想保留所有精确数据？把 `data_precision` 改成 `exact`
- 想允许脏话？把 `allow_profanity` 改成 `true`
- 想新增禁用词？把词加到 `ban_words` 数组里

### 让 AI 一次完成改写 + 诊断 + 验收

如果你不想分步执行，可以发这个**超级 Prompt** 给 AI：

```
你的任务：把下面这段 AI 文字改写成"一个有经验的朋友在认真分享"的风格，
去掉念报告的味道，但保留实用价值。不要灌水，不要跑题，不要没正形。
⚠️ 强制要求：不要缩减任何内容，原文有多少要点改写后就要保留多少。

【原文】
{你的文本}

【工作流程】
1. 先改写一版，风格像靠谱的朋友在分享经验，内容要完整
2. 然后站在"挑剔读者"的角度检查这版，找出 AI 残留
3. 针对问题再改一版
4. 重复 2-3 步，直到读起来像真人写的实用分享
5. 输出最终版本

【判别标准】
- 不像真人的：标准结构、套话词汇、念报告语气、过度工整、缺乏经验凭据、
  面面俱到的端水、结尾划重点
- 像真人的：有具体经验、有场景感、语气自然像在聊事情、
  口语化但不飘、段落顺序不像在列清单

【输出】
{
  "final": "最终改写结果",
  "content_preserved": true,
  "iterations": [...]
}
```
