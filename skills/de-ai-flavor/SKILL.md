# 去AI味 - De-AI-Flavor

把 AI 生成的文本改成自然的人类写作风格。

## 核心思路

```
❌ 旧思路：维护一个禁用词清单 → 用关键词匹配检测 → 把禁用词替换掉
✅ 新思路：让 AI 自己识别 AI 特征 → 让 AI 自己改写 → 让 AI 自己验收
```

**核心原则：不缩减内容。** 改写的目标是改变风格，不是删减信息。所有原文里的要点、细节、数据都必须保留，只改变说话的方式。

---

## 配置文件

在 `de-ai-flavor/config.json` 中可以自定义改写行为。关键配置项：

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `persona` | 改写后的说话角色 | 靠谱朋友 |
| `style_level` | 口语化程度 1-10 | 6 |
| `allow_profanity` | 是否允许脏话 | false |
| `allow_humor` | 是否允许吐槽、自嘲 | true |
| `allow_interruptions` | 是否允许突然跑题 | false |
| `personal_experience` | 个人经历密度 | some |
| `length_control` | 长度控制 | preserve |
| `data_precision` | 数据精确度 | fuzzy |
| `max_revision_iterations` | 最大修订轮数 | 3 |
| `ban_words` | 额外禁用词 | [] |
| `output_format` | 输出格式 | plain |

**快捷预设**：直接在 `preset_profiles` 里引用预设名称：

```
标准知识分享    → 靠谱朋友风格，口语度适中
技术博客        → 技术博主风格，保留精确数据
论坛问答        → 论坛老手风格，允许跑题
职场沟通        → 职场前辈风格，最克制
```

修改 `config.json` 后，AI 会自动读取并应用配置，不需要改动 Prompt。

## 工作流程

```
┌─────────────────────────────────────────────────┐
│  第0步：读取配置 (Load Config)                  │
│  读取 config.json，按配置生成个性化 Prompt       │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  第一步：作者改写 (Draft)                        │
│  AI 扮演配置指定的角色，按配置风格改写原文        │
│  ⚠️ 核心原则：原文字数一个都不能少              │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  第二步：质检员诊断 (Diagnose)                   │
│  AI 扮演"质检员"角色，检查是否还有 AI 特征       │
│  ⚠️ 诊断时检查：内容是否完整，有无遗漏           │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  第三步：对照诊断结果再次改写 (Revise)           │
│  把诊断出来的具体问题逐条修复                    │

└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  第四步：验收 (Accept)                           │
│  达到"靠谱朋友在认真分享"的标准才通过           │
└─────────────────────────────────────────────────┘
```

## 第零步：读取配置，生成个性化 Prompt

执行改写前，先读 `config.json` 中的配置项，然后按以下规则生成个性化 Prompt 片段：

### 角色（persona）

```
- 靠谱朋友：说话实用、有经验、不飘不灌水
- 技术博主：有条理、有深度、有亲和感
- 论坛老手：经验十足、偶尔吐槽、不废话
- 资深用户：稳重、有判断力、不极端
- 职场前辈：有见地、有分寸、适度保守
```

### 口语化程度（style_level 1-10）

```
1-3：几乎不口语，保持书面感
4-6：轻微到中等口语（默认 6）
7-9：较口语化，可以吐槽
```

### 语气允许项

```
允许自然口语，但程度取决于 allow_profanity / allow_humor / allow_interruptions：
- 温和口语：说实话、我跟你说、基本上、大概
- 吐槽/幽默：需要 allow_humor = true
- 脏话：需要 allow_profanity = true
- 跑题/打断：需要 allow_interruptions = true
```

### 长度控制（length_control）

```
preserve：保持原文长度，所有要点完整保留（默认）
expand：  允许适度扩展，补充细节
condense：允许精简，去除冗余（不推荐，容易丢信息）
```

### 数据精度（data_precision）

```
exact：保持原文精确数据（'50%'、'3.2.0'）
fuzzy：数据模糊化（'大概一半'、'最新版'）（默认）
```

## 第一步：作者改写 Prompt

把以下 Prompt 完整发给 AI，把 `{配置片段}` 替换为根据 config.json 生成的内容：

```
你现在是一个中文写作者，风格像一个{persona}在认真跟你讲他踩过的坑。
他说话靠谱、不装，但也不飘，不是不务正业的那种没正形。

【写作目标】
把下面这段 AI 生成的文字，改写成一个{persona}在真实场景下会写的分享。
重点：去掉"念报告"的味道，保留"靠谱实用"的气质。
⚠️ 重要：不要缩减任何内容！原文有多少要点，改写后就要保留多少。
    改写的目标只是改变说话风格，不是删减信息。

【原文】
{original_text}

【改写要求】
1. 说话靠谱、实用，像一个认真分享经验的人，而不是在灌水
2. 第一人称：我、我们
3. 语气像在跟朋友聊事情，不是写文档，不是做汇报
4. 允许自然口语：{口语词示例}
   {如果 allow_profanity = true}可以偶尔用：破玩意儿、坑爹、心都在滴血
   {如果 allow_humor = true}允许适度吐槽、自嘲
   {如果 allow_interruptions = true}允许突然换话题、自我打断（"等等我刚才说到哪了"）
5. 长短句交替，不要每句话都一样长
6. 加入{personal_experience}处具体的个人经历或场景细节（让经验有凭据）
7. {data_precision_desc}
8. 允许暴露不确定的地方，但不要跑题
9. 不要用以下东西：
   - "首先/其次/最后"、"综上所述"、"值得注意的是"
   - "赋能"、"痛点"、"底层逻辑"
   - 教科书式标题【XX】【XX】
   - 整齐的分隔线 =========
   - ⚠️ 这种 emoji 装饰
   {如果额外禁用词存在}- 额外禁用：{ban_words}
10. 段落衔接自然，可以有点跳跃，但不要没正形地乱跳
11. 【强制要求】保持原文长度，不要缩减任何内容。
       原文有几个要点，改写后就要有几个要点，一字不能少。

【输出】
直接输出改写后的文字，不要任何解释。
```

## 第二步：质检员诊断 Prompt

改写完后，把原文和改写结果发给 AI，让它自己挑刺：

```
你现在是一个中文编辑，专门帮作者去掉文章里的 AI 味。
你的工作是从"读者"的角度判断：这篇文章读起来像真人写的吗？
同时要检查：内容是否完整，有没有遗漏原文的要点？

【原文】
{original_text}

【改写后】
{rewritten_text}

【诊断维度】从以下几个角度打分，每个维度 0-10 分（10 分 = 完全像真人）：

1. 【结构】有没有标准化的"总分总"、"教科书式标题"、"整齐分隔线"
2. 【词汇】有没有 AI 套话（赋能、痛点、底层逻辑、首先其次最后等）
3. 【语气】像不像人在说话，还是像在念报告
4. 【个体经验】有没有具体的个人经历、场景、感官细节
5. 【情绪】有没有真实的情绪波动（吐槽、犹豫、后悔）
6. 【不完美感】有没有暴露思考局限、偏见、不确定的地方
7. 【困惑度】上下文衔接是不是太顺畅，有没有跳跃感
8. 【突发性】句子长短是不是有变化，还是四平八稳
9. 【端水感】有没有过分平衡的两面论证（虽然...但是...）
10. 【符号装饰】有没有 emoji、过度对齐的分隔线

【内容完整性检查】
- 改写后的内容是否完整保留了原文的所有要点？
- 有没有遗漏任何信息？（如果有，即使其他分数高，severity 也应为 high）

【输出格式】
{
  "scores": {
    "结构": 8,
    "词汇": 7,
    ...
  },
  "content_completeness": {
    "complete": true | false,
    "missing_points": ["如果有遗漏，列出被删除的要点"]
  },
  "ai_residue": [
    "第2段还是太工整了，像在念报告",
    "'与此同时'这个连接词很AI"
  ],
  "improvements": [
    "把第2段的'XX。XX。XX。'改成有长有短的句子",
    "..."
  ],
  "verdict": "pass" | "revise"
}
```

---

## 第三步：对照诊断再次改写 Prompt

如果诊断结果是 `revise`，把改进建议发给 AI，让它针对性修复：

```
你的文章被编辑挑出了以下几个问题。请逐条修复：

【诊断问题】
{improvements}

【上一次的改写】
{previous_rewrite}

【要求】
- 保留你原来写得好的部分
- 只针对上面的问题改
- 【强制要求】仍然保持原文长度，不要缩减任何内容

【输出】
直接输出修复后的完整文章。
```

---

## 第四步：验收标准

通过验收的条件（同时满足）：

| 维度 | 通过条件 |
|------|----------|
| 结构 | 没有【XX】【XX】标题、没有 ====== 分隔线 |
| 词汇 | 质检员 10 个维度平均分 ≥ 7 |
| 语气 | 出现至少 3 处口语化表达（"说实话"、"大概"等） |
| 个体经验 | 至少 1 处"我试了..."、"我遇到..."的描述 |
| 情绪 | 至少 1 处真实情绪（吐槽、后悔等） |
| 内容完整 | 改写后内容与原文要点数量一致，无遗漏 |
| 长度 | 改写后字数 ≥ 原文字数 |

如果任意一项不满足，返回第三步修复。

最多循环 `max_revision_iterations` 次（默认 3 次），超过则输出当前最佳版本。

### 用户提供的原文（不缩减版）

```
GPT-6 Astra 这玩意儿，说来也真够折腾人的。

赶紧登网页版查了一下，没事，那就是这模型权限没给我开。

后来翻 Reddit 才搞明白，OpenAI 这边是分批放的。免费账号就别想了，
直接绕道。我当时 Plus 也不行，等了差不多两天，再试就好了。
网上有人说 Pro 和企业版会快一些，我估计是吧，反正 Plus 用户
就只能干等。

噢对，我那会儿还卡在一个更蠢的坑里——版本太老。我 Codex 一直
停在 3.1.X 没更新，结果更到最新版那个选项才冒出来。
这个坑我同事也踩过，他当时以为是网络问题，折腾了半天才发现
是版本的事。

要是你等不及权限开放，另一种思路是直接搞 API Key，绕过账号登录
体系。我身边有个朋友就是这么干的，他在 OpenAI 开发者平台
申请了一个，然后把 Codex 切到 API 认证。

不过那个价格你得心里有数。输入 10 块、输出 50 块一百万 Token，
听着好像还行？但这模型跑起来是真的费钱。我自己测的时候，
一个不算大的活跑了大概四五轮，输出花了我二十多块，
当时就想着，这要是拿来写长文档我得破产。

还有一茬，这东西额度消耗得比我想的快得多。免费额度基本撑不过
一次像样的活，Pro 用户据说一次任务能掉将近五分之一的额度。
我那天晚上试了几次还赶上服务器满载报错，重试了三次才成功，
估计大家都挤着用。

反正这事儿吧，就这么回事。新模型刚出来的时候，权限、版本、额度、
服务器，每一个都有可能坑你一遍。准备好耐心，多试几次，
或者干脆换个工具用，别死磕。
```

## 进阶：让 AI 自己当质检员

如果你想让 AI 一次性完成改写 + 诊断 + 验收，可以一次性发这个超级 Prompt：

```
你的任务：把下面这段 AI 文字改写成"一个有经验的朋友在认真分享"的风格，
去掉念报告的味道，但保留实用价值。不要灌水，不要跑题，不要没正形。
⚠️ 强制要求：不要缩减任何内容，原文有多少要点改写后就要保留多少。

【原文】
{original_text}

【工作流程】
1. 先改写一版，风格像靠谱的朋友在分享经验，内容要完整
2. 然后站在"挑剔读者"的角度检查这版，找出 AI 残留
3. 针对问题再改一版
4. 重复 2-3 步，直到读起来像真人写的实用分享
5. 输出最终版本

【判别标准】
- 不像真人的：标准结构、套话词汇、念报告语气、过度工整、缺乏经验凭据、
  面面俱到的端水、结尾划重点
- 像真人的：有具体经验、有场景感、语气自然像在聊事情、
  口语化但不飘、段落顺序不像在列清单

【内容检查】
- 改写后是否保留了原文所有要点？
- 字数是否 ≥ 原文字数？

【输出】
{
  "final": "最终改写结果",
  "content_preserved": true | false,
  "iterations": [
    {"version": 1, "rewrite": "...", "diagnosis": "..."},
    {"version": 2, "rewrite": "...", "diagnosis": "..."}
  ]
}
```

这个 Prompt 适合快速场景。如果想精细控制质量，还是用前面四步分开的方式。
