# 去AI味 - 详细参考资料

本文档提供去AI味改写策略的详细说明和Prompt设计方法。

## 一、如何精准识别"AI味"

### 1.1 机械的连接词与结构

AI生成的文本往往过度使用模板化过渡词：

| 类别 | 典型词汇 | 出现频率 |
|------|----------|----------|
| 序列词 | 首先、其次、再次、最后、第一步、第二步 | 极高 |
| 总结词 | 综上所述、总而言之、总之、简而言之 | 极高 |
| 强调词 | 值得注意的是、值得强调的是、必须指出 | 高 |
| 转折词 | 然而、因此、与此同时、此外 | 中高 |

### 1.2 句式与节奏过于均匀

AI生成的句子具有以下特征：
- 句子长度高度一致（标准差 < 3）
- 段落长度均匀分布
- 缺乏人类写作中的"跳跃感"和"呼吸感"

**健康的人类写作**：
- 短句：5-15字
- 中句：15-30字
- 长句：30-50字
- 随机混合，有明显的节奏变化

### 1.3 高频套话与抽象词汇

| 类别 | 典型词汇 |
|------|----------|
| 商业黑话 | 赋能、痛点、底层逻辑、生态、闭环、赛道、破局 |
| 空洞形容词 | 显著提升、至关重要、不可或缺、深远意义 |
| 否定对比 | 不是X，而是Y、不是...恰恰是... |

### 1.4 缺乏个人视角与真实细节

**AI文本特征**：
- 全文无"我"字，或仅有1-2处
- 缺乏具体时间（"去年"、"大概三年前"）
- 缺乏具体地点和场景描写
- 缺乏感官细节（气味、触感、声音）
- 语言完美无瑕，缺乏情感张力

### 1.5 特定的标点与冗余习惯

- 过度使用破折号（—）制造转折
- 段末进行无意义的总结复述
- 频繁使用括号进行补充说明

## 二、核心改写策略与Prompt设计

### 2.1 角色设定与语气软化

**目标**: 不要让AI以"客观上帝视角"生成，而是赋予其具体身份和主观立场。

**Prompt示例**:
```
请扮演一位有5年经验的产品经理，正在和非技术背景的朋友解释这个问题。
用轻松吐槽的语气，带点个人偏见和局限性认知。
全程使用"我"的视角，加入"说实话"、"怎么看呢"、"我个人觉得"等口头禅。
```

**核心要点**:
- 给AI具体身份
- 允许主观偏见
- 要求暴露局限性
- 强制使用第一人称

### 2.2 结构打散与节奏重构

**目标**: 打破AI的"完美平滑感"，制造人类写作的自然跳跃。

**Prompt示例**:
```
禁止使用以下连接词：首先、其次、再次、最后、因此、然而、此外、与此同时
禁止使用：综上所述、总而言之、值得注意的是
打破"总分总"结构，不要求结论先行
采用长短句交替：至少包含3处5-8字的短句，至少包含2处25-35字的长句
允许段落以疑问句或未完结感收尾
段落之间的衔接可以生硬，直接跳话题也是可以的
```

**句长比例参考**:
- 短句（<15字）: 30%
- 中句（15-30字）: 50%
- 长句（>30字）: 20%

### 2.3 注入真实细节与人类痕迹

**目标**: 用具体的动作、感官和故事替代抽象的陈述。

**Prompt示例**:
```
将文中的抽象词汇替换为具体动作：
- "赋能" → "让...变得更好用"
- "痛点" → "让人头疼的问题"
- "关键" → "最影响结果的"

加入以下真实细节（选择2-3处植入）：
- 具体时间：去年、前几天、大概三个月前
- 具体场景：办公室、医院、地铁上
- 感官细节：闻起来、听起来、摸起来的感觉
- 个人故事：我的经历、我朋友的故事

允许出现轻微口语化冗余：
- "这个方法，还真是挺有效的，至少对我来说"
- "说实话，这个问题我也想了很久"
- "怎么说呢，当时就是觉得..."
```

### 2.4 设立严格的"禁用黑名单"

**完整禁止清单**:

```
词汇类：
赋能、痛点、底层逻辑、生态、闭环、赛道、破局、显著提升、至关重要、
不可或缺、深远意义、值得注意的是、综上所述、总而言之、首先、其次、
再次、最后、第一、第二、第三、因此、然而、与此同时、此外、不言而喻、
不言而明、从某种意义上来说、从本质上来看、本质上、核心、关键、
发挥着重要作用、具有重要意义

句式类：
- 连续使用排比句（超过2个）
- "不是X，而是Y"否定对比结构
- "总分总"标准框架
- 段末强行升华或总结
- 机械的因果连接

结构类：
- 引言+正文+结论的标准三段式
- 严格按照"提出问题-分析问题-解决问题"框架
- 段落长度完全均匀
```

## 三、八大Prompt改写策略

### Prompt 1: 口语化重写

```
在跟朋友聊天一样重写以下内容。可以加入语气词、反问句，用不太规范但生活化的表达。
不要用"首先、其次、最后"这种结构。
```

### Prompt 2: 特定身份代入

```
假设你是一个有5年经验的研究生导师，正在非正式场合给学生讲解这个问题。
语言风格要自然随意，可以夹杂一些个人看法和吐槽。
```

### Prompt 3: 加入不确定性表达

```
在讨论观点时，适当加入一些不确定性的表达：
- "我个人觉得"
- "可能不一定对"
- "据我了解"
- "我记得之前看到过"
不要每句话都很肯定，真实的人写东西不会那么绝对。
```

### Prompt 4: 知乎风格

```
用知乎高赞回答的风格来写：
- 开头可以先讲一个小故事或抛出一个反常识的观点
- 中间用具体经历和数据支撑
- 偶尔可以自嘲一下
```

### Prompt 5: 学术口语混搭

```
这是一篇学术论文的内容，请在保持学术性的基础上，让语言更自然一些：
- 把可以简化的长句拆短
- 把过于书面的表达换成学术圈口头常用的说法
- 可以使用"大概"、"差不多"等模糊词
```

### Prompt 6: 情感化表达

```
融入适当的情感和主观判断：
- 对某个现象表示惊讶
- 对某个数据表示意外
- 对某个结论表示犹豫
人类写东西是有情绪波动的，不要全程冷静客观。
```

### Prompt 7: 碎片化思维

```
不要用完美的逻辑链条来组织内容：
- 可以在中间插入一些联想、题外话
- 然后再拉回主题
- 整体结构可以稍微松散
- 段落之间的过渡不要太丝滑
```

### Prompt 8: 方言和网络用语

```
适当使用一些当下流行的网络用语和口头禅，但不要太多，大概每三四段用一两个就行：
- "绝了"
- "真的会谢"
- "属于是"
- "咱就是说"
- "懂的都懂"
```

## 四、打破论述模式

### 4.1 打乱论述顺序

- 不要按照"提出问题-分析问题-解决问题"的标准框架
- 可以先说结论，再回头解释为什么
- 或者从一个具体案例切入，再展开讨论

### 4.2 插入个人经历

在论述过程中，插入2-3段个人经历或观察：
- "我之前遇到过..."
- "我有个朋友..."
- "上次我试着..."

### 4.3 保留不完美

- 可以在文章中明确说"这个问题我也没完全想清楚"
- 或者"这方面我了解得不够深入"
- 展现真实的知识局限性

### 4.4 非线性引用

引用数据或观点时，不要每次都规规矩矩地"根据XXX研究表明"：
- "我记得之前看到过一个数据"
- "好像是XX年的一个报告里提到"
- "有个研究说..."

### 4.5 段落间的跳跃

段落之间的过渡不要太丝滑：
- 人类写作经常是想到什么写什么
- 段落之间的衔接可以稍微生硬
- 甚至可以直接换话题

## 五、语言细节处理

### 5.1 同义词随机化

对于同一个概念，在文章不同位置使用不同的说法：
- "人工智能" → 交替使用"AI"、"机器智能"、"智能算法"
- 不要全文统一用一种说法

### 5.2 缩略语和简称

适当使用缩略语和行业简称：
- 第一次出现时可以标注一下，后面直接用简称
- 比如"人工智能（AI）"后面就直接用"AI"

### 5.3 控制连接词

减少"然而"、"因此"、"此外"这类连接词的使用频率：
- 人类写作不会每段都用过渡词
- 有时候直接开始新的内容就行

### 5.4 口头禅植入

给文章设定2-3个反复出现的口头禅：
- "说白了"
- "怎么说呢"
- "反正我是觉得"
- "说实话"

### 5.5 数据表述人性化

引用数据时不要总是"XX为XX%"：
- 可以说"大概有一半左右"
- "差不多三分之二"
- "将近九成"
- 用更模糊但更人性化的方式

## 六、质量检查清单

改写完成后，使用以下清单进行检查：

### 6.1 词汇检查
- [ ] 无禁止词汇
- [ ] 同一概念使用了多种表达
- [ ] 无过度使用连接词

### 6.2 句式检查
- [ ] 长短句混合
- [ ] 句长标准差 > 3
- [ ] 无连续排比句

### 6.3 结构检查
- [ ] 非标准总分总结构
- [ ] 有段落跳跃或生硬衔接
- [ ] 无段末强行总结

### 6.4 人性化检查
- [ ] 包含"我"字至少3处
- [ ] 有具体时间或场景
- [ ] 有个人经历或故事
- [ ] 有情感表达

### 6.5 整体检查
- [ ] 读起来像人写的
- [ ] 有明显的个人风格
- [ ] 逻辑不必完美但自然

## 七、常见问题处理

### 7.1 改写后逻辑不通

**问题**: 过度改写导致逻辑混乱
**解决**: 保持核心论点不变，只改变表达方式和结构

### 7.2 口语化过度

**问题**: 改写成大白话，失去了专业性
**解决**: 根据场景调整口语化程度，学术场合保持一定书面语

### 7.3 禁用词替换困难

**问题**: 某些抽象词难以用具体表达替换
**解决**: 可以用"某个方法"、"这种情况"等模糊表达替代

### 7.4 个人经历不够

**问题**: 用户的原文缺乏可供延伸的经历
**解决**: 可以创造合理的假设性经历，并标注"假设场景"

## 八、不同场景的改写策略

### 8.1 学术论文
- 保持学术严谨性
- 口语化程度：低
- 个人视角：适度（"笔者认为"）

### 8.2 商业文案
- 保持专业度
- 口语化程度：中
- 可适当使用行业黑话（但避免过度）

### 8.3 社交媒体
- 高度口语化
- 允许网络用语
- 允许情绪化表达

### 8.4 技术文档
- 保持准确性
- 口语化程度：低
- 避免主观判断

### 8.5 日常交流
- 完全口语化
- 允许碎片化
- 允许不完整表达
